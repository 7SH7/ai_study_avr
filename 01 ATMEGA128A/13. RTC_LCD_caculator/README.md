## 1. 개요

하나의 장치에서 **시계(RTC) / 계산기 / 시간 수정** 세 가지 모드를 버튼으로 전환한다.
시간은 I2C RTC 칩(DS1307)에서 읽어 LCD에 표시하고, 계산기 모드에서는 4×4 키패드 입력으로 사칙연산을 수행한다.

## 2. 하드웨어 구성

## 3. 시스템 아키텍처

### 3.1 동작 모드 FSM

```
        BTN4                     BTN3
 RTC_CLOCK ───────► CALCULATOR   RTC_CLOCK ⇄ RTC_CHG_MODE
  (시계 표시)        (키패드 계산)   (시간 수정: BTN2로 항목 선택 yy→mm→dd→hh→min→sec,
                                                BTN0/1로 값 −/＋)
```

| 모드 | 설명 |
|---|---|
| `RTC_CLOCK` | DS1307에서 시각 read → LCD에 달력/시계 출력 |
| `CALCULATOR` | 키패드 입력을 큐에 쌓아 사칙연산 처리, 60초 무입력 시 시계로 복귀 |
| `RTC_CHG_MODE` | 연·월·일·시·분·초 항목별 증감으로 시간 설정 |

**2단 FSM 구조**: `program_stat`(모드) × `chg_clock_stat`(시간 수정 시 어느 항목인지) 두 축으로 상태를 나눠, 모드가 늘어나도 조건문이 곱해지지 않게 했다.

### 3.2 파일 구성

| 파일 | 역할 | 담당 |
|---|---|---|
| `main.c` | 3모드 FSM, 버튼 입력 처리, 시간 항목 증감 | 본인 |
| `ds1307.c` | I2C RTC read/write, BCD 변환, 달력 출력 | 본인 |

## 4. 핵심 구현 포인트 (면접 설명용)

### 4.1 I2C DS1307 RTC — BCD ↔ Decimal 변환

DS1307은 시간을 **BCD(Binary Coded Decimal)** 로 저장한다. 예를 들어 십진수 `59`는 `0x59`로 담긴다.
그대로 읽으면 89가 되므로 읽을 때 `bcd2dec`, 쓸 때 `dec2bcd` 변환이 필요하다.

```c
typedef struct { uint8_t seconds, minutes, hours, date, month, dayofweek, year, ampm, hourmode; } t_ds1307;
```

→ 시각 정보를 구조체로 캡슐화해, 읽기/쓰기/표시 함수가 개별 변수 대신 하나의 단위를 주고받게 했다.

**왜 데이터시트를 봐야 했는가**: 레지스터 주소(0x00~0x06)와 각 비트의 의미(12/24시간 모드 비트, CH 비트)는
칩 데이터시트에만 있다. 라이브러리 없이 구현하려면 레지스터 맵을 직접 읽어야 했다.

### 4.2 Timer0 ISR 키패드 스캔 + 원형 큐 버퍼링

```c
ISR(TIMER0_OVF_vect){
    TCNT0 = 6;
    if (program_stat == CALCULATOR){
        idle_counter++;
        if (++keypad_counter >= 60){                 // 주기적 스캔 (약 60 tick마다)
            keypad_counter = 0;
            uint8_t k = keypad_scan();
            if (k != 0) insert_queue(k);             // 입력을 큐에 적재 (ISR은 짧게)
        }
    }
}
```

→ ISR에서는 **스캔·큐 적재만** 하고, 실제 계산은 메인 루프(`cal_main`)에서 처리한다.
**입력(생산)과 처리(소비)를 분리**한 구조 — ISR이 길어지면 다른 인터럽트가 밀리기 때문.

### 4.3 idle 타임아웃

계산기 모드에서 `idle_counter`가 `TIMEOUT_MS`(60초)를 넘으면 자동으로 시계 모드로 복귀한다.
"기능"이 아니라 **사용성** 관점의 설계 — 탁상 장치는 기본 화면이 시계여야 한다는 판단.

## 8. 배운 점

- RTC 칩의 **BCD 포맷**과 I2C 통신 절차를 데이터시트 기반으로 구현했다. 라이브러리를 쓰지 않으니 레지스터 맵을 읽는 것 외에 방법이 없었고, 그 과정이 곧 학습이었다.
- **ISR은 짧게(스캔·적재), 무거운 처리는 메인 루프로** — 인터럽트 설계의 기본 원칙을 몸으로 익혔다.
- 큐 자료구조로 입력을 버퍼링하면 **생산 속도와 소비 속도가 달라도 데이터를 잃지 않는다.**
- 2단 FSM(모드 × 세부 항목)으로 나누면 조건문이 곱해지지 않는다.
