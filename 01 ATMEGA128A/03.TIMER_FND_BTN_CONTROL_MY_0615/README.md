# FND 시계 / 스톱워치 (TIMER2 오버플로 인터럽트 기반)

> [`02.FND_CONTROL_MY_0612`](../02.FND_CONTROL_MY_0612/ReadME.md)의 `_delay_ms` 방식을
> **타이머 인터럽트 기반 시간 측정**으로 승격시킨 버전.

| 항목 | 내용 |
|---|---|
| MCU | ATmega128A (`F_CPU` = 16MHz) |
| 개발 환경 | Atmel Studio / AVR-GCC |
| 핵심 기술 | TIMER2 오버플로 인터럽트, FND 소프트웨어 멀티플렉싱, FSM, `volatile` 공유변수 |
| 담당 역할 | 개인 실습 (⚠️ [확인 필요] — 아래 "저자 표기" 참조) |

---

## 1. 개요

4자리 7-Segment FND(Common Cathode)를 소프트웨어 멀티플렉싱으로 제어하며, BTN0으로 세 가지 모드를 순환한다.

- **모드 0**: 분:초 시계 (1초마다 콜론 점멸)
- **모드 1**: 초 단위 카운터 + "SEC" 표시
- **모드 2**: 스톱워치 — BTN1 시작/정지, BTN2 리셋

**02와의 차이**: 시간의 기준을 메인 루프에서 떼어내 하드웨어 타이머로 옮겼다.

| | 02 (`_delay_ms`) | 03 (TIMER2 인터럽트) |
|---|---|---|
| 시간 기준 | `_delay_ms(1)` 후 `ms_count++` | `ISR(TIMER2_OVF_vect)`에서 `ms_count++` |
| 메인 루프 | delay에 묶여 **블로킹** | **논블로킹** — 계속 돈다 |
| 오차 원인 | FND 출력·연산 시간이 그대로 누적 | 타이머 분주 설정에서만 발생 |
| 공유 변수 | 없음 (단일 흐름) | `volatile uint32_t ms_count` (ISR ↔ main) |

| 부품 | 연결 | 비고 |

| 버튼 × 3 | BTN0 / BTN1 / BTN2 | `button.h` 참조 |

## 3. 시스템 아키텍처

### 3-1. 파일 구성

| 파일 | 역할 |
|---|---|
| `main.c` | TIMER2 초기화, ISR 정의, 모드/상태 분기 |
| `button.c` / `button.h` | 버튼 디바운싱, "눌렀다 뗀 순간" 1회 이벤트 검출 |
| `fnd.c` / `fnd.h` | FND 멀티플렉싱 출력, 카운트 갱신 |

### 3-2. 상태 전이 (FSM)

```
                 BTN0            BTN0            BTN0
  [모드0 분:초] ──────> [모드1 초] ──────> [모드2 스톱워치] ──────> (모드0으로 순환)

  모드2 내부:
      ┌── BTN1 ──┐
      v          │
  [SW_STOP] ──BTN1──> [SW_RUN]
      │                  ^
      └── BTN2(리셋) ────┘   (리셋 후 다시 BTN2를 누르면 RUN)
```

모드 전환(BTN0) 시 `ms_count`, `sec_count`, `dot_display`를 모두 0으로 되돌리고 `sw_state`를 `SW_STOP`으로 초기화한다.

## 4. 핵심 구현 포인트 (면접 설명용)

### 4-1. TIMER2 분주비와 프리로드 값 — 숫자의 근거

```c
void init_timer2(void)
{
    TCNT2 = 194;
    TCCR2 = 0x00;
    TCCR2 |= 1 << CS22 | 0 << CS21 | 0 << CS20;  // 256분주
    TIMSK |= 1 << TOIE2;                          // TIMER2 Overflow 인터럽트 허용
    sei();
}
```

ATmega128의 TIMER2는 8비트 타이머라 **255에서 오버플로**한다. 원하는 주기를 만들려면 매번 시작값(`TCNT2`)을 다시 넣어줘야 한다.

| 항목 | 계산 |
|---|---|
| 타이머 클럭 | 16 MHz ÷ 256 = **62.5 kHz** |
| 1 tick | 1 ÷ 62.5 kHz = **16 µs** |
| 오버플로까지 | 256 − 194 = **62 tick** |
| 실제 주기 | 62 × 16 µs = **992 µs** |

> ⚠️ **정확히 1 ms가 아니다 (−0.8% 오차).** 1 ms를 만들려면 62.5 tick이 필요한데 정수가 아니기 때문이다.
> 1000초가 지나면 약 8초 어긋난다.

**주석 처리된 조합이 오히려 정확하다:**

```c
//TCNT2 = 6;
//TCCR2 |= 0 << CS22 | 1 << CS21 | 1 << CS20;  // 64분주
```

| 항목 | 계산 |
|---|---|
| 타이머 클럭 | 16 MHz ÷ 64 = 250 kHz → 1 tick = **4 µs** |
| 오버플로까지 | 256 − 6 = **250 tick** |
| 실제 주기 | 250 × 4 µs = **1000 µs 정확** |

→ ⚠️ **[확인 필요]** 정확한 64분주 조합을 두고 256분주를 선택한 이유를 확인해 문서에 반영할 것.
(ISR 호출 빈도를 낮추려는 의도였다면 그 자체가 좋은 설계 근거가 된다.)

### 4-2. `volatile`이 필요한 이유

```c
volatile uint32_t ms_count = 0;

ISR(TIMER2_OVF_vect)
{
    TCNT2 = 194;
    ms_count++;
}
```

`ms_count`는 **ISR이 바꾸고 메인 루프가 읽는** 변수다. `volatile`이 없으면 컴파일러가 "메인 루프 안에서 이 값이 바뀔 리 없다"고 판단해 레지스터에 캐싱하고, 루프가 영원히 옛 값을 보게 된다.

### 4-3. 공유 변수 보호 — `cli()` / `sei()`

```c
if (get_button(BUTTON0, BUTTON0PIN))
{
    cli();
    ms_count = 0;   // 공유되는 값 보존을 위해..
    sei();
    ...
}
```

ATmega128은 **8비트 MCU**인데 `ms_count`는 32비트다. 즉 대입 한 줄이 어셈블리에서는 **4번의 바이트 접근**으로 쪼개진다. 그 사이에 ISR이 끼어들면 값이 찢어진다(torn read/write).

→ 이래서 임계 구역을 `cli()` / `sei()`로 감쌌다.

## 6. 알려진 한계 / 개선 여지

정직하게 남긴다. 동작은 하지만 구조적으로 더 나은 방법이 있는 지점들이다.

| # | 항목 | 현재 | 더 나은 방법 |
|---|---|---|---|
| 1 | 1ms 정확도 | 992 µs (−0.8%) | 64분주 + `TCNT2 = 6` 또는 **CTC 모드 + `OCR2`** (프리로드 자체가 불필요해짐) |
| 2 | 스톱워치 일시정지 | `sw_state`에 따라 `cli()` / `sei()`로 **전역 인터럽트를 껐다 켬** | 전역 인터럽트를 끄면 타이머 외 다른 인터럽트도 함께 멈춘다. **`run` 플래그**를 두고 ISR 안에서 판단하는 편이 안전 |
| 3 | 임계 구역 누락 | BTN2 리셋 경로의 `ms_count = 0`은 `cli()` 보호가 없음 | 동일하게 보호하거나 `ATOMIC_BLOCK()` 매크로 사용 |
| 4 | 비원자적 read-modify-write | `fnd.c`의 `if(ms_count >= 1000) { ms_count = 0; sec_count++; }` | 읽기·수정·쓰기 전체를 임계 구역으로 |
| 5 | 시간 계산 위치 | 초 환산이 `fnd.c`(출력 담당)에 섞여 있음 | 시간 관리와 표시를 분리 |

→ 2·3·4는 모두 **"ISR과 메인 루프가 같은 변수를 만진다"** 는 하나의 주제다.
STM32 프로젝트([`03 ARM_Lab/9999. motor_pro`](../../03%20ARM_Lab/9999.%20motor_pro/))에서 같은 문제를 다시 만나 더 정리된 방식으로 다뤘다.

## 7. 배운 점

- **시간의 기준을 소프트웨어 지연에서 하드웨어 타이머로 옮기면 메인 루프가 자유로워진다.** 논블로킹 구조의 출발점.
- **8비트 MCU에서 32비트 변수는 원자적이지 않다.** `volatile`은 컴파일러 최적화를 막을 뿐, 원자성은 보장하지 않는다 — 둘은 다른 문제다.
- 타이머 설정값(`TCNT2`, 분주비)은 **데이터시트의 분주 표에서 역산해 나오는 숫자**이지 외워서 쓰는 값이 아니다.
