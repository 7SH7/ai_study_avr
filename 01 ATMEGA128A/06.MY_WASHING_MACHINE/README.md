# 🧺 세탁기 컨트롤러 — FSM 기반 임베디드 제어

> ATmega128A · 베어메탈 C · 상태머신(FSM) 설계 · **개인 프로젝트**

| 구분 | 내용 |
|---|---|
| **한 줄 소개** | 대기→세탁→헹굼→탈수 사이클과 각 단계 시간설정을 버튼으로 제어하는 세탁기 펌웨어 |
| **MCU / 환경** | ATmega128A (16 MHz, 베어메탈) · Microchip Studio |
| **핵심 기술** | `enum` 기반 FSM · Timer0 ISR(1ms 틱 + FND 멀티플렉싱 + 카운트다운) · Timer3 고속 PWM 모터 · 버튼 이벤트 처리 |
| **담당 역할** | **전체 단독 개발** (설계·구현·디버깅) |

---

## 1. 개요

실제 세탁기의 동작 흐름을 **유한 상태 기계(FSM)** 로 모델링했다.
사용자가 세탁 / 헹굼 / 탈수 시간을 각각 설정하고 시작하면, 각 단계가 타이머로 카운트다운되며 자동으로 다음 단계로 전이된다.

**개발 목표**
- 세탁 사이클 전체를 상태도로 먼저 정의하고 코드와 1:1 대응시키기
- 시간 표시(FND)와 카운트다운을 메인 루프에서 분리해 인터럽트로 처리
- 모터를 단순 on/off가 아니라 PWM 속도 변화로 제어

## 2. 하드웨어 구성

| 부품 | 연결 | 용도 |
|---|---|---|
| MCU | ATmega128A (16 MHz) | 메인 제어 |
| 4-digit 7-Segment FND (Common Cathode) | 세그먼트 `PORTC` / 자리선택 `PORTB 4~7` | 설정 시간 · 남은 시간 표시 |
| LED × 8 | `PORTA` | 동작 단계 상태 표시 |
| 버튼 × 4 | `PORTD 3~6` (active-high) | 시작/정지 · 단계 선택 · 시간 증가 |
| DC 모터 + 드라이버 | `PE5` (= `OC3C`, Timer3 PWM 출력) | 세탁조 구동 |

> 핀 근거: `fnd.h`(`FND_DATA_PORT`/`FND_DIGIT_PORT`), `button.h`(`BUTTON_PIN = PIND`), `led.c`(`DDRA`), `pwm.c`(`DDRE |= 1<<5`, `OCR3C`)

## 3. 시스템 아키텍처

### 3.1 상태 정의 (FSM)

```
                 ┌─────────── standby (대기) ───────────┐
        BTN1     │   BTN0(start, 단 세 시간 모두 설정 시)  │  BTN0(정지)
   ┌────────────▼──────────┐                             │
   │ wash_time_set          │  wash → rinse → spin →  standby
   │ → rinse_time_set       │   (각 단계 시간 0 되면 자동 전이)
   │ → spin_time_set        │   BTN2: 분(min) 증가
   └────────────────────────┘
```

| 상태 | 설명 |
|---|---|
| `standby_state` | 대기 (LED off) |
| `wash_state` / `rinse_state` / `spin_state` | 세탁·헹굼·탈수 실행 (LED 패턴 + PWM 모터 + FND 카운트다운) |
| `*_time_set` | 각 단계 시간 설정 (BTN2로 분 증가) |

### 3.2 타이머 자원 배치

| 타이머 | 역할 | 설정 근거 |
|---|---|---|
| **Timer0** | 1 ms 틱 — FND 멀티플렉싱 출력 + 1초 카운트다운 | `TCNT0 = 6` 프리로드, 오버플로 인터럽트 |
| **Timer3** | 모터 PWM | 8비트 고속 PWM(모드 5), 64분주 → 250 kHz ÷ 256 ≈ **977 Hz**, `OCR3C`로 듀티 조절 |

> 표시(Timer0)와 구동(Timer3)을 **서로 다른 타이머에 분리**해 한쪽 부하가 다른 쪽 주기에 영향을 주지 않게 했다.

### 3.3 파일 구성

| 파일 | 역할 |
|---|---|
| `main.c` | FSM 상태 전이 (버튼 입력 + 시간종료 이벤트) |
| `washing_machine.c / .h` | 각 단계 실행 (LED/모터/FND 갱신, 남은시간 반환) |
| `fnd.c / .h` | FND 멀티플렉싱 출력 |
| `timer.c / .h` | Timer0 1 ms 틱 |
| `pwm.c / .h` | Timer3 PWM 모터 제어 |
| `led.c / .h` | 상태 LED (`PORTA`) |
| `button.c / .h` | 버튼 디바운싱 · 눌렀다 뗀 순간 1회 이벤트 |
| `uart0.c / .h` | UART 디버그 출력 |

> ℹ️ `ultrasonic.c / .h`는 이전 실습에서 함께 복사된 파일로 **본 프로젝트에서는 호출되지 않는다.** (정리 대상)

## 4. 핵심 구현 포인트 (면접 설명용)

### 4.1 상태 전이 제약조건 방어

```c
if (machine_state == standby_state && wash_time && rinse_time && spin_time) {
    machine_state = wash_state;      // 세 단계 시간이 모두 설정돼야만 시작 허용
}
```

→ "시간 미설정 시 시작 불가" 같은 **비정상 입력을 상태 전이 단계에서 차단**했다.
조건을 실행 함수 안이 아니라 **전이 조건**에 둔 것이 포인트 — 상태도의 화살표에 조건이 붙는 형태와 1:1로 대응한다.

### 4.2 시간 종료를 "이벤트"로 삼는 자동 전이

```c
if (machine_state == wash_state && !wash_running()) {   // 카운트다운 종료
    machine_state = rinse_state;
    current_fnd_washing_value = rinse_time * 60;         // 다음 단계 초기화
}
```

→ 각 단계 실행 함수가 **남은 시간을 반환**하고, 0이 되면 다음 상태로 넘어가는 틱 기반 이벤트 구조.
메인 루프는 "지금 어떤 상태인가"만 판단하고, 시간 계산은 ISR이 담당한다.

### 4.3 Timer0 ISR에서 FND 멀티플렉싱 + 1초 카운트다운

```c
ISR(TIMER0_OVF_vect){
    TCNT0 = 6;  static int ms = 0;
    if (is_use_timer_set_status)          time_set_fnd(current_fnd_setting_value);   // 설정값 표시
    else if (is_use_timer_running_washmach){
        wash_running_express_fnd(current_fnd_washing_value);                         // 멀티플렉싱 출력
        if (++ms >= 1000){ if (current_fnd_washing_value>0) current_fnd_washing_value--; ms=0; }  // 1초마다 감소
    } else fnd_all_off();
}
```

**왜 FND를 ISR에서 갱신하는가**
FND 소프트웨어 멀티플렉싱은 **일정한 주기로 자리를 바꿔야** 잔상이 유지된다.
메인 루프가 버튼 처리·상태 전이에 묶이면 갱신 주기가 흔들려 화면이 깜빡인다.
→ 주기가 보장되어야 하는 작업은 ISR로, 순서만 맞으면 되는 작업은 메인 루프로 나눴다.

### 4.4 모터 속도 프로파일 (단순 on/off가 아님)

```c
void wash_running_dc_motor(void)
{
    static int speed = 200;
    static int direction = 1;

    if(speed > 200) speed = 200;
    else speed = speed + (10 * direction);

    OCR3C = speed;

    if(speed > 200) direction = -1;      // 상한 도달 → 감속으로 전환
    else if(speed < 50) direction = +1;  // 하한 도달 → 가속으로 전환
}
```

→ `OCR3C`를 50 ↔ 200 사이에서 왕복시켜 **가속·감속이 반복되는 삼각파 속도 프로파일**을 만들었다.
실제 세탁기의 정·역 교반 동작을 속도 변화로 흉내낸 것.

> ℹ️ 방향 전환(H-브릿지 IN1/IN2)은 구현하지 않았고 **PWM 듀티에 의한 속도 제어만** 수행한다.

## 8. 배운 점 / 개선 여지

**배운 점**
- 사이클 전체를 **상태도 → 코드 1:1 대응**으로 설계하는 감각. 상태도에 없는 분기가 곧 버그였다.
- **주기가 보장되어야 하는 일(FND 멀티플렉싱)과 순서만 맞으면 되는 일(상태 전이)** 을 구분해 ISR/메인 루프에 배치하는 기준을 잡았다.
- 타이머를 용도별로 나누면 서로의 타이밍에 간섭하지 않는다.

**개선 여지 (인지하고 있으나 미적용)**

| # | 항목 | 현재 | 개선 방향 |
|---|---|---|---|
| 1 | 모터 재설정 | `wash_running()`이 매 루프 `wash_running_dc_motor()` 호출 → 불필요한 반복 | 상태 **진입 시 1회만** 설정 (entry action) |
| 2 | 플래그 초기화 | `standby`에서 실행 플래그를 매 루프 초기화 | 상태 진입 시 1회 처리로 정리 |
| 3 | 미사용 파일 | `ultrasonic.c/.h`가 빌드에 포함되어 있으나 호출되지 않음 | 제거 |
| 4 | 방향 제어 | PWM 속도만 제어, 정·역 전환 없음 | H-브릿지 IN1/IN2로 실제 교반 동작 구현 |

→ 1·2는 **"상태 진입 시 한 번(entry) vs 상태 유지 중 매번(during)"** 을 구분하지 않은 데서 온 같은 문제다.
FSM을 entry / during / exit 세 단계로 나누는 설계는 이후 STM32 프로젝트에서 정리했다.
