# FND 시계 / 스톱워치 (폴링 · `_delay_ms` 기반)

## 과제 개요

ATmega128A(`F_CPU` 16MHz) 기반으로 **4자리 7-Segment FND(Common Cathode)** 를 소프트웨어 멀티플렉싱으로 제어하여, 버튼 입력에 따라 세 가지 모드를 전환하는 펌웨어.

- **모드 0**: 분:초 시계 (1초마다 dot/콜론 점멸)
- **모드 1**: 초 단위 카운터 + "SEC" 텍스트 표시
- **모드 2**: 스톱워치 (run / stop / reset)

BTN0으로 모드를 순환 전환하고, 모드 2에서는 BTN1로 시작/정지, BTN2로 리셋을 수행한다.

시간 측정은 `_delay_ms(1)` 호출 뒤 `ms_count++` 하는 **소프트웨어 지연 방식**이다.
→ 이 방식의 한계를 타이머 인터럽트로 해결한 것이 [`03.TIMER_FND_BTN_CONTROL_MY_0615`](../03.TIMER_FND_BTN_CONTROL_MY_0615/README.md)이다.

### 파일 구성

| 파일 | 역할 |
|---|---|
| `main.c` | 버튼 입력 감지 및 모드/상태 분기 |
| `button.c` / `button.h` | 버튼 디바운싱, "눌렀다 뗀 순간" 1회 이벤트 검출 |
| `fnd.c` / `fnd.h` | FND 멀티플렉싱 출력, 시계/스톱워치 카운트 갱신 |

## 이 과제에서 배울 만한 점

### 1. 소프트웨어 멀티플렉싱과 `static` 변수의 위험성

FND 4자리를 한 핀 세트로 제어하기 위해 `digit_select`라는 `static` 변수로 "현재 어느 자리를 출력 중인지"를 추적한다. 이 변수는 **함수가 호출될 때마다 정확히 1씩 증가**해야 자리 순서가 맞는다.

→ **배울 점**: `static` 변수로 상태를 유지하는 함수는 **호출 횟수와 호출 시점이 곧 출력 결과에 직접 영향**을 준다. 호출 빈도가 조건문에 따라 달라지면(한 루프에서 2번 호출되는 경우와 1번 호출되는 경우가 섞이면) 멀티플렉싱 동기가 깨져 화면이 깜빡이거나 자리가 뒤섞인다.

### 2. "버튼 누적 카운트" vs "이벤트 기반 상태 전환"

초기 코드는 `button1_state++`, `button2_state++` 처럼 누른 횟수를 계속 누적하고 `% 2`로 토글을 흉내냈다. 이 방식은:

- 변수가 무한히 증가 (이론상 오버플로우 가능)
- 조건이 늘어날수록 `% 2`, `> 1` 같은 조건 조합이 복잡해지고 가독성이 떨어짐
- **실수로 추가 분기(`else if`)가 부작용 있는 함수를 한 번 더 호출**하게 만들기 쉬움

→ **배울 점**: 버튼 입력처럼 "발생한 이벤트"는 **그 순간 한 번만 처리**하고, 시스템의 현재 상태는 `enum` 같은 명시적 상태 변수로 따로 관리하는 게 안전하다. (상태머신 패턴)

### 3. 상태도를 먼저 그리고 코드로 옮기는 작업의 가치

손으로 그린 상태도(분·초시계 ↔ 초시계 ↔ 스톱워치, 그리고 스톱워치 내부의 stop/run/reset)를 코드와 대조해보면, **코드가 그림의 상태/전환을 1:1로 표현하지 못하는 지점이 곧 버그**였다. 특히 "reset 후 자동으로 run 상태가 된다"는 전환을 코드가 누락했던 것이 대표적.

→ **배울 점**: 상태도를 먼저 정의하면 "이 상태에서 이 입력이 들어오면 어디로 가야 하는가"가 명확해지고, 코드 리뷰 시 "이 분기가 상태도의 어느 화살표에 대응하는가"를 체크리스트처럼 확인할 수 있다.

### 4. `#if 0` 죽은 코드(dead code)의 누적 비용

Common Anode / Cathode 분기를 `#if 0 ... #else ... #endif`로 모든 함수마다 반복해두면, 코드량이 2배가 되고 실제 사용 중인 분기를 찾기 위해 매번 시각적으로 걸러내야 한다.

→ **배울 점**: 결정이 끝난 분기는 버전 관리(git)에 맡기고 소스에서는 제거하는 것이 유지보수성을 높인다.

### 5. 헤더의 `extern` 선언과 실제 구현의 불일치

`fnd.h`에 `reset_stop_watch()`가 선언돼 있었지만 어디에도 정의되지 않았고, `main.c`도 호출하지 않았다. 호출이 없으니 링크 에러도 안 나서 컴파일은 통과한다. **설계 의도와 실제 코드가 어긋난 흔적**이었다.

→ **배울 점**: 선언만 있고 구현/호출이 없는 함수는 "구현하다가 다른 방식으로 우회한" 흔적일 수 있다. 정리하거나 의도를 주석으로 남겨야 한다.

## 핵심 수정 요약

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 스톱워치 상태 | `button1_state`, `button2_state` 누적 변수 + `% 2` | `sw_state_t sw_state` (`SW_STOP` / `SW_RUN`) 단일 상태 |
| BTN2(리셋) 처리 | 부작용으로 `stopwatch_clock()` 중복 호출 → `digit_select` 동기 깨짐 | 중복 호출 제거 |
| 상태 전환 | "reset → run" 전환 누락 | 코드에 명시적으로 반영 |
| 죽은 코드 | `#if 0` Common Anode 분기 전체 | 제거 |
| 미사용 선언 | `reset_stop_watch()` | 제거 |
| 콜론 표시 | `find_display()`의 분 단위(case 2, 3)에 미적용 | `dot_display` 일관 적용 |
